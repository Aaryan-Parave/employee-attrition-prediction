# Employee Attrition Prediction
### Decision Tree Classifier — Academic AIML Lab Submission

---

## Problem Statement

Employee attrition (voluntary turnover) is one of the most expensive operational challenges for organisations. Replacing a single employee costs an estimated 50–200% of their annual salary when accounting for recruiting, onboarding, and lost productivity.
This project builds an interpretable machine-learning model that predicts which employees are likely to leave, so that HR teams can intervene early. A **Decision Tree** is chosen deliberately — it produces human-readable decision rules that HR managers can audit and act on, unlike black-box models such as neural networks or gradient boosting ensembles.

## Why Decision Tree?

> **HR decisions must be explainable.** If a model flags an employee as a flight
> risk, an HR manager needs to say *why* — e.g., "This employee works overtime,
> has low job satisfaction, and has been here less than 2 years." A Decision Tree
> produces exactly this kind of rule, traceable from root to leaf.

## Results

| Metric | Value |
|--------|-------|
| Accuracy | 78.57% |
| Precision (Yes) | 46.67% |
| **Recall (Yes)** | **11.29%** ← primary metric |
| F1-Score (Yes) | 18.18% |

### Why Recall is the Primary Metric

The dataset is class-imbalanced (~16% Yes). A naive model that always predicts
"No" achieves ~84% accuracy while catching **zero** actual quitters.

- **False Negative** (predict Stay → actually Leaves) = employee quits without
  warning → recruiting cost, knowledge loss. **High cost.**
- **False Positive** (predict Leave → actually Stays) = HR has an unnecessary
  retention conversation. **Low cost.**

Therefore we optimise and report **Recall for the "Yes" (Leave) class**.

### Top 3 Features Driving Attrition

1. **OverTime** (importance: 0.1832) — employees working overtime are significantly more likely to quit
2. **DistanceFromHome** (importance: 0.1367) — long commute employees show higher attrition
3. **MonthlyIncome** (importance: 0.1149) — lower-paid employees are at higher risk

### Overfitting Comparison

| Model | Train Accuracy | Test Accuracy | Gap |
|-------|---------------|---------------|-----|
| Unbounded tree | 100.00% | 68.03% | **31.97%** ← overfitting |
| Pruned (depth=5) | 82.99% | 78.57% | 4.42% ← generalising |

## Limitations

1. **Class imbalance not explicitly handled** — we highlight Recall but do not
   apply SMOTE or `class_weight='balanced'`. A real deployment would address this.
2. **No hyperparameter tuning** — `max_depth=5` was chosen heuristically based on
   dataset size and standard practice. Cross-validated grid search would improve this.
3. **Dataset size** — 1 470 rows is small by ML standards. Models trained on it
   may not generalise to organisations with very different demographics.
4. **LabelEncoding ordinal assumption** — LabelEncoder assigns arbitrary integers
   to nominal categories (e.g., Department). For linear models this would be
   incorrect; Decision Trees are largely unaffected but OneHotEncoder would be
   more rigorous.
5. **Single algorithm** — no comparison against Logistic Regression or Random
   Forest to quantify the accuracy-explainability trade-off numerically.
6. **Synthetic data** — this submission uses a synthetic dataset that mirrors the
   IBM schema. Results may differ with the real dataset.
